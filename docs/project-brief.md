# ShopMate 电商商家操作 Agent 项目简报

## 问题与目标用户

小型电商商家和店铺运营人员需要在订单、商品和售后页面之间切换，重复查询状态、整理导出数据和录入信息。本项目面向近期商家试用准备一个可演示的操作 Agent，展示自然语言任务理解、计划预览、浏览器执行和操作留痕。

## 主要场景与 MVP

- 按订单号、商品或状态查询订单，并导出当前筛选结果。
- 查询商品与库存；提交库存或售价变更计划，展示对象和前后值，确认后执行。
- 检查待发货订单，预览运单信息，确认后录入并检查状态。
- 查询售后申请与状态；当前不批准/拒绝售后，也不执行退款。
- 在操作台查看每次任务结果、浏览器操作步骤、截图和本地操作记录。

## 排除范围

当前不连接淘宝、天猫、拼多多、抖店等真实商家后台，不读取真实账户，不收发客服消息、不执行真实发货、退款或付款。未实现多商家租户、云端部署、团队权限、生产监控和平台授权流程。

## 产品形态与业务模式

Windows 本地运行的单店铺 Web 原型，由 FastAPI 同时提供操作台、API 和演示商家后台。现阶段为学习与试用验证项目，没有收费或商业化承诺。

## 数据与安全

SQLite 使用虚构店铺、订单、商品和售后样例。写操作需在操作台确认；浏览器执行器使用独立 Playwright 上下文，只能访问本机固定演示站点。登录令牌不传入前端脚本，浏览器仅获得当前任务的本地会话 Cookie。真实试用前须完成店铺授权、租户隔离、密钥保管、权限设计、日志脱敏、备份及审计保留。

## 技术方向

Python、FastAPI、SQLite、LangGraph、Playwright、原生 JavaScript。任务意图和参数采用可解释规则映射；浏览器只执行预定义动作，不接受任意 URL 或用户提供的脚本。未来接入真实平台时优先评估官方授权 API，再为获准场景实现平台适配器；API 不覆盖时再评估合规的页面操作方式。

## 里程碑与验收标准

1. 完成本地业务数据、操作计划和确认接口。
2. 完成演示商家后台和商家操作台的浏览器闭环。
3. 完成启动说明、边界说明、手工验证和面试讲解资料。

验收以本地浏览器可登录、查询订单、导出 CSV、查询商品/售后、预览库存/价格/发货变更并在确认后完成模拟执行为准。结果应能回看截图与记录；错误或字段不足时应要求补充，不得自行猜测目标。

## 风险与当前限制

模拟页面验证不了真实平台接口稳定性、店铺授权、验证码策略、风控与平台合规。浏览器执行依赖本机 Chrome；本地单进程登录令牌存内存，不能直接对公网或多商户开放。商家试用前需要先选定平台并完成安全及业务验收。
