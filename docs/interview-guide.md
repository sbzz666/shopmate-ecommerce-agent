# ShopMate 电商商家操作 Agent：项目讲解

## 项目介绍

“ShopMate 是一个面向中国电商运营流程的本地操作 Agent 原型。运营人员可以用自然语言查询订单、导出订单、查询商品库存和售后记录；对库存、售价和发货信息，系统先生成可核对的计划，确认后由 Playwright 操作本地模拟商家后台。后端使用 FastAPI 与 SQLite 保存演示业务数据和操作记录，LangGraph 组织任务理解与计划生成。当前没有接入任何真实电商平台。”

## 简历描述参考

**ShopMate 电商商家操作 Agent｜个人实战项目**

- 基于 FastAPI、LangGraph、SQLite 与 Playwright 构建电商运营后台操作原型，实现订单查询/导出、商品库存与售价查询、售后查询及模拟发货。
- 设计“任务解析—结构化计划—高风险写操作确认—浏览器执行—结果核对”的操作流程，保存执行状态、步骤、截图和 CSV 导出记录。
- 将浏览器执行器限制为预定义动作和固定本地模拟站点；对库存、售价和发货写操作增加字段验证及确认闸门。

根据自己实际理解和完成情况调整简历，不要描述成已接入真实平台或生产系统，也不要虚构业务收益。

## 面试问题

**为什么用浏览器自动化？**

它能把后台页面交互过程直观演示出来，适合本地原型验证 Agent 如何填写筛选条件、点击页面动作并核验结果。真实平台若有官方授权 API，应优先走 API；本项目的 Playwright 只在模拟站点验证流程。

**为什么写操作要确认？**

库存、售价和发货信息会改变业务状态。Agent 先展示目标商品/订单和将写入的值，操作者确认后才运行浏览器动作。查询和导出是只读操作，可以直接执行。

**LangGraph 在哪里发挥作用？**

当前图将意图识别与计划生成拆成节点，明确输出操作类型、参数、需补充信息和确认要求。任务识别目前是规则式实现，LangGraph 提供可扩展的流程结构，并不意味着系统已用大模型自主决策。

**真实接入淘宝、拼多多或抖店需要什么？**

先确定平台与目标店铺，申请平台认可的应用资质，取得商家明确授权并核验 API 的权限范围和审核要求。随后实现独立平台适配器、凭证安全存储、租户隔离、限流、幂等、审计、错误重试和对账。只有官方 API 不覆盖且平台规则允许时，才评估受控的浏览器自动化。

**当前版本不能做什么？**

不能访问真实店铺、自动回复顾客、执行真实退款或付款、批准售后或批量调价。数据是本地虚构样例，单进程令牌保存在内存中，不能直接当作公网上线的多商户 SaaS。

**下一步如何验证商家价值？**

与一位明确授权的商家选定一个低风险、只读流程，记录人工处理步骤和耗时，先通过官方接口拉取数据并与后台结果比对；再逐步试用需要确认的写操作。关注任务成功率、结果准确率、平均处理时间、人工接管率和异常恢复情况，不在没有实测前声称节省比例。

## 建议演示顺序

1. 登录 `operator / operator123`，查询待发货订单。
2. 导出订单 CSV 并查看任务结果。
3. 查询商品 SKU，发起库存或售价变更，在预览里核对后确认。
4. 对待发货订单录入演示运单并确认，回到模拟后台检查状态。
5. 查询待审核售后记录，展示当前只读边界。
